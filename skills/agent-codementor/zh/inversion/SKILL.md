# Skill: 反向设计与品味分析

命令：`/inversion`

当用户问为什么代码这样设计、为什么复杂、为什么不用更简单实现时使用。

## 目标

反向推导作者的取舍：这段复杂性在防止什么灾难，优化什么，又牺牲什么。

## 输出契约

1. **结论先行**：指出这份复杂性主要在防止哪类灾难。
2. **朴素设计**：构造用户脑中可能想到的更简单实现。
3. **它会在哪里崩**：从吞吐、内存、延迟、同步、缓存复用、碎片、取消或回滚压力分析失败点。
4. **防御性代码点**：指出看起来复杂但在保护正确性或性能的代码。
5. **取舍表**：包含 `Design choice`、`Gain`、`Cost` 三列。
6. **品味判断**：说明复杂性是必要、过度设计、位置错误还是合理折中。
7. **什么条件下可以安全简化**：指出哪个条件、不变量或上游 API 变化会让简单方案变得可行。
8. **阅读检查点**：指出下一个能确认或削弱判断的源码位置。

## 硬约束

- 不只说“为了性能”。
- 不只赞美设计。
- 必须和更简单方案比较。
- 必须说清当前设计的代价。
