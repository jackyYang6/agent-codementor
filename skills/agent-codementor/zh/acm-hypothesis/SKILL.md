# Skill: 理解假设批判

命令：`/acm-hypothesis`

当用户提出心智模型、说“我认为……”“是不是……”，或要求找漏洞时使用。

## 目标

在非顺利路径下验证用户理解，暴露缺失的 20%。

## 输出契约

1. **结论先行**：明确说明这个模型正确、部分正确还是错误。
2. **重写主张**：用一句精确的话改写用户的理解。
3. **提取隐藏假设**：把用户主张拆成 3-5 个假设。
4. **逐条批判假设**：说明何时成立、何时失败、在哪里能从源码验证。
5. **强制边界场景**：至少覆盖三类：取消、并发竞态、OOM 回滚、缓存失效、重复释放、usage 不匹配、背压、部分失败、多 worker 不一致、流式 final chunk、speculative rollback。
6. **修正后的心智模型**：把用户模型改写得更精确。
7. **仍然重要的未知点**：指出在修改代码前还必须找到、但当前没有确认的源码证据。
8. **一个验证任务**：最后给出一个源码级问题让用户检查。

## 硬约束

- 不使用“基本对”这种模糊鼓励。
- 不只讨论 happy path。
- 没有源码级推理时不要反驳。
